## 三、分阶段执行计划(采纳 Codex 阶段0-5,含验收)

- **阶段 0 ✅ 已完成**:frontier_lite 全绿(run `20260706T130626`)+ 基线定档(批跑进行中,结果写入本目录)。
- **阶段 1 ✅ 已完成(2026-07-06 晚,实测)**:gbplanner-ref 单侧复验通过——三节点在、voxblox tsdf 4.098Hz、起飞 z=1.2008、automatic_planning success、**自主移动到 (5.73,0.26,1.39)**、`/rmf_obelix/command/trajectory` 抓到实轨迹(证据 `runbooks/world-model-jazzy/stage1_evidence.txt`)。**关键新事实**:①trajectory 是**事件式**发布(每次规划一条,非连续流)→适配器按"收到一条跟踪一条"设计;②waypoint 的 velocities/accelerations 全 0,只有位置+四元数+time_from_start(50ms 步长)→**必须做位置→速度转换**;③**TF 对照(实测)**:GBPlanner odometry=`world→rmf_obelix/base_link`、点云 frame=`rmf_obelix/rmf_obelix/velodyne`(嵌套命名空间)、trajectory frame=`world`;world-model=/slam/odom `map→base_link` → 桥接需 `world↔map` 映射(静态 TF/改 launch 的 world_frame 参数)。
- **阶段 2 ✅ PASS(2026-07-06 晚,B2.5 自写薄桥)**:transport 三段实测通——①ROS2→ROS1 odom(字段原样,34条,stage2e A)②ROS2 scan→ROS1 PointCloud2(width=3,stage2e B)③ROS1 trajectory→ROS2 `/gbp/trajectory`(rclpy 订阅收 2 条 145/180wp,frame 已映射 world→map,stage2j)。**两条实验教训**:a)jazzy `ros2 topic echo` CLI 对 rclpy 发布者收不到(stage2i 矩阵:rclpy→rclpy 60/60、rclpy→CLI 0)——**验收一律用 rclpy 订阅**;b)⚠️ 遗留(不绕过):TCP 在 2~3 条后被对端关闭且重连静默失败(两端异常日志不全)→ **阶段 2.5 必修**:双端 connect/send 失败日志 + ping 心跳 + SO_KEEPALIVE,复跑锁根因后才进阶段 3。
- **阶段 3**:`trajectory_to_intent.py` dry-run——只打印 waypoint/distance/yaw error,校 frame/时间戳/方向;按查证#3 改成速度型输出。
- **阶段 4**:低速短程接 FCU(限速 0.1m/s、短窗口、可停),验收=intent 非零、controller ready、path_length 增长、不干扰 takeoff(B15 门保护)。
- **阶段 5**:补 gate 话题(查证#4 的字段清单),与 frontier_lite 基线同口径对比(accepted_goals/path_length/rosbag/summary)。
- **GUI 三演示**:阶段 5 全部跑通后建(用户指示)。

## 五、当前真实架构(B2.5 自写薄桥,Codex 桥接 review 采纳)

```
world-model ROS2(jazzy)                          GBPlanner ROS1(noetic, gbplanner_ref 容器)
  /slam/odom ──┐                                        ┌── /wm/odom(nav_msgs/Odometry)
  /scan ───────┤ thinbridge_ros2_side.py                │   /wm/points(PointCloud2 xyz32)
  (将来 cloud_in 3D) │  odom 限频10Hz→JSON               │        │(阶段2.6 remap 给 gbplanner/voxblox)
               │  scan→xyz JSON(冒烟)                    │        ▼
               └──── TCP :7601(4B长度+JSON)────── thinbridge_ros1_side.py
               ┌─────────────────────────────────────────┘
  /gbp/trajectory(frame=map)◄── trajectory JSON ◄── /rmf_obelix/command/trajectory(事件式)
        │
        ▼(阶段3 dry-run→阶段4 低速)
  trajectory_to_intent.py(骨架,输入已改 /gbp/trajectory)
        │ 位置航点→机体速度意图(intent 契约=linear_x_mps/linear_y_mps/yaw_rate_radps)
        ▼
  /navlab/fcu/setpoint/intent(+阶段5 补 /navlab/exploration/status 等 gate 字段)
```

**关键分界线(Codex P1,记住)**:阶段 2 只证明 transport;**"GBPlanner 接入 world-model"的判据 = GBPlanner 真的消费 /wm/odom + /wm/points 做规划**(阶段 2.6:remap/relay 到 gbplanner/voxblox 实际订阅的 topic,验证 trajectory 随输入变化),否则只是"两个仿真系统旁路通信"。
