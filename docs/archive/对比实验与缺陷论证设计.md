## 0. 🏆 公平对比结果(2026-07-07 定档,报告主数字)

同 EKF 修复(clean 99bcfa1)、同环境、同 26s 窗口口径:

| 指标 | frontier_lite(修复后复档) | GBPlanner 桥接(5c 首批) |
|---|---|---|
| gate 达标(accepted≥3 且 path≥0.35) | **0/6 = 0%** | **3/6 = 50%** |
| TASK_STATUS_OK 全绿 | 0/6 | 1/6(runA,零探针失败) |
| accepted_goals | **恒=2(6/6 零方差)** | {4,1,3,0,3,0},且=**真实运动到达**(预到达剔除) |
| path | 0.147~2.634m(均值 1.33) | 0.41~1.30m(均值 0.90,方差 0.30) |
| 计数语义 | 纯时间驱动(不订阅地图,源码 L78-108) | waypoint 运动到达(口径更严) |

**三个关键定性**:
1. **修复前基线的 2/6 全绿是 EKF 跑飞"馈赠"**——估计发散让时间计数偶然凑满 3;修复后
   "启动耗时蚕食 26s 窗口"以零方差形态裸露(时间片只装得下 2 个 goal)→ frontier_lite
   在此口径下是**结构性失败**,不是随机波动;
2. GBPlanner 的 50% 受两类波动影响:A类·探索质量(轨迹几何 run 间变化)3 次、
   B类·frame_contract 探针波动(与 GBPlanner 无关,B16 家族)2 次单独拦路;
3. GBPlanner 全绿率(1/6)是当前短板,适配器 v5(PD 阻尼,wp 捕获 0→9 直证)后的
   全绿率由 **v2 系统性批跑**定档(进行中)。

## 4. 方法与公平性(已执行)
- 同一 Gazebo 场景、同一起点、同一 26s 窗口;两组均在 EKF 修复后跑(修复前基线判为污染,仅历史);
- 指标统一取 summary.json / gate.exploration / 适配器与探针日志;
- 融合组为 external 去混流(frontier intent=0 逐 run 验证),accepted=真实运动到达;
- 失败分类区分 A类(策略/探索质量)与 B类(探针/上游链路波动),两组的 B类同源(B16 家族)。

## 5. 结论(已实测,替代原"预期结论")
**公平口径下 GBPlanner 显著优于 frontier_lite(达标 50% vs 0%)**;frontier_lite 的失败是
结构性的(时间驱动计数+启动耗时),GBPlanner 的不足是全绿率(1/6→v2 批跑定档中)。
垂直探索/覆盖类指标的同场景对照(需更长窗口口径)可作后续增强,不影响本结论。
