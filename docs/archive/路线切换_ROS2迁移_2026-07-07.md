# 路线切换:放弃桥接,GBPlanner 迁移 ROS2 原生

## 一、指示与理由

导师指示(2026-07-07):**一定要把 GBPlanner 算法转移到 ROS2 系统,彻底抛弃桥接方案**。
理由:ROS1+ROS2 两套系统同时跑过于笨重(两个 ROS 栈、TCP 桥、双容器生态、
DDS/XmlRpc 双重脆弱面——今晚演示中 RViz XmlRpc 崩、探针 DDS 匹配退化均为佐证)。

## 二、桥接线的处置(冻结,不清零)

桥接方案(B2.5)定性为**已完成的过渡阶段**,冻结为两个用途:
1. **Oracle 回归基准**:ROS1 原版 GBPlanner(gbplanner_ref 镜像)+ 桥接联跑证据链
   (4c 归因/5a gate/5b 3D 对照/5c 对比)保留,ROS2 版行为等价性对照全靠它;
2. **科研叙事素材**:公平对比(GBPlanner 50% vs frontier_lite 0%)、三大鸿沟、
   失真补证等结论仍然成立——它们证明的是"GBPlanner 算法在 world-model 中有效",
   与运载方式(桥/原生)无关。
桥接代码(thinbridge/gbplanner_ref 容器编排)不再演进,不再修 bug。

## 四、迁移蓝图(三层拆分,ROS1 版为 oracle)

```text

B 地图接口层  voxblox —— 选型进行中(官方无 ROS2 版;社区 fork/nvblox/自移植,行为等价优先)
C ROS2 外壳层 rclcpp 节点 + 参数 + 服务;PCI 预判可弃(由薄壳+适配器直连替代,契约文档定)

```
