## 3. 精确桥接映射(就按这个接)
| GBPlanner(ROS1)需要 | world-model(ROS2)对接 | 处理 |
|---|---|---|
| `/<robot>/velodyne_points`(3D 点云) | ❌ **world-model 只有 2D `/scan`** | **见缺口①** |

| 输出 `command/trajectory`(MultiDOF) | `/navlab/exploration/goal` + `/navlab/fcu/setpoint/intent` | **见缺口②** |

## 4. 两个"现在必须定死、后期改不动"的硬缺口

### 缺口① 3D 点云 vs 2D 激光(最关键)
- GBPlanner 的体积增益**必须吃 3D PointCloud2**;world-model 无人机(`navlab_iq_quad`)只有 **2D 平面雷达**(model.sdf:42 `scan_ideal` 361×**垂直1线**)。
- **把 2D `/scan` 转成 PointCloud2 也只是一个平面,撑不起 3D 探索。**
- **结论(早定死)**:必须给仿真无人机**加 3D 雷达**(Velodyne/Livox 多线 gpu_lidar),直接发 `velodyne_points`。否则桥接做完也跑不出真正 3D 探索 → 后期返工。

### 缺口② 输出格式:MultiDOFJointTrajectory vs MAVLink setpoint
- GBPlanner 经 PCI 发 `command/trajectory`(给 RotorS 控制器);world-model 用 **ArduPilot + `/navlab/fcu/setpoint/intent`**。
- **结论(早定死)**:桥接需写一个**适配节点**,把 GBPlanner 的轨迹/航点转成 world-model 的 `setpoint/intent`(经唯一 FCU controller,P8 设计:探索器只能发 intent,不能直发 cmd_vel)。

## 5. ros1_bridge 注意
- 自定义消息(`planner_msgs`、`MultiDOFJointTrajectory`)需在 bridge 显式映射;标准消息(Odometry/PointCloud2/LaserScan)自动桥。
- 详细桥接清单在桥接落地阶段(任务#4)按本规格逐条实现。

## 6. GBPlanner 传感器模型 + 3D 雷达改造(缺口①的精确解)
**GBPlanner 期望的传感器(gbplanner_config.yaml:21-30,真实):**
- 型号 `OS064`(Ouster OS0-64,3D LiDAR),`max_range = 20.0 m`
- FOV = **[2π 水平, π/2 垂直]** = 360° × 90°(±45°);角分辨率 7°×7°
- 建图体素(voxblox_sim_config.yaml:5):`tsdf_voxel_size = 0.20 m`
- 增益(gbplanner_config.yaml:139-143):`unknown_voxel_gain 60.0`、`path_length_penalty 0.04`、`path_direction_penalty 0.1`(= 我 P1 实现的距离/转向惩罚,方向印证)

**给 `navlab_iq_quad` 加的 3D 雷达(对齐 OS064,新增到 model.sdf):**
```xml
<sensor name="lidar3d" type="gpu_lidar">
  <topic>/points3d</topic>
  <gz_frame_id>velodyne</gz_frame_id>
  <update_rate>10</update_rate>
  <always_on>true</always_on>
  <ray>
    <scan>
      <horizontal><samples>360</samples><min_angle>-3.14159</min_angle><max_angle>3.14159</max_angle></horizontal>
      <!-- 垂直 ±45° = π/2,对齐 OS064 的 90° 垂直 FOV -->
      <vertical><samples>32</samples><min_angle>-0.785398</min_angle><max_angle>0.785398</max_angle></vertical>
    </scan>
    <range><min>0.1</min><max>20.0</max></range> <!-- 对齐 max_range 20m -->
  </ray>
</sensor>
```
- gz 的 `gpu_lidar`(垂直多线)会输出 PointCloud2 → `ros_gz_bridge` 桥成 ROS2 `/points3d` → 改名/桥到 GBPlanner 的 `/<robot>/velodyne_points`。
- 这样仿真雷达的 FOV/range 与 GBPlanner 的 OS064 模型对齐,体积增益计算才正确(否则后期增益失真、全盘返工)。
