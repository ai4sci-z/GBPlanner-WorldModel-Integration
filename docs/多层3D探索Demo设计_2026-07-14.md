## 0. 一句话目标

> GPS-denied 室内环境 → 3D LiDAR/SLAM/TSDF-ESDF → GBPlanner 选出**有 z 变化**的探索路径
> → 飞控**真实执行上升/下降** → 至少一次跨层探索,全程可复现、可量化。

## 1. 三层诚实边界(汇报口径,禁止越线)

### 1.1 算法层已支持(有证据)
- GBPlanner 本体是 3D 探索规划器(RRG 采样含 z、raycast 算未知**体积**增益)——桥接期 5b 实证:
  改 lidar 垂直 FOV(±30°→±5°)→ 输入云 zspan 19× 压缩 → trajectory zspan 收缩一个量级。
- M2 voxblox ROS2 移植数值对拍 PASS(TSDF 零失配 + ESDF RMS 2.5e-05)。
- M5 bring-up run(20260714T095739)中 ROS2 planner 对真场景输出的轨迹 z 有明显变化(0.42/0.38/-0.15)。

## 3. 场景路线(从简到繁,先 S1/S2)

- **S1 两层平台 + 斜坡 ramp**(首选:几何最简单,点云/碰撞干净)
- **S2 两层平台 + 宽楼梯**
- S3 螺旋坡道 / S4 多层迷宫+竖井 / S5 狭窄楼梯间(远期)

**设计铁律:场景必须"非 3D 不可"**——平面策略在一层绕不出去,只有升到二层/坡道口
才能看到新未知空间;2D 投影图会把楼层混叠出歧义。否则证明不了 3D-aware 增益。

## 4. 评测指标(gate 之外必录,由独立 evaluator 计算,禁止执行 adapter 自报)

```text
explored_volume_m3        探索 3D 体积
height_coverage           覆盖的高度层数/比例
zspan_trajectory          轨迹 z 范围
z_active_ratio            含 z 变化的轨迹段比例
floor_transition_success  跨层成功(核心判据)
new_voxels_per_meter      单位路径新增体素
collision_clearance_min   最小障碍距离(ESDF)
time_to_second_floor      到达二层耗时
```

对照组:frontier_lite 同场景同预算同 gate(预期:困在一层,height_coverage≈1 层)。

## 5. z 控制接口设计约束(M5-4 前必须核对,不许拍脑袋选型)

1. 三选一须以 FCU 主路径实测为准:vertical velocity / relative altitude / 3D position setpoint
   (world-model fcu 主路是"胡萝卜"位置目标——大概率 3D position setpoint 最贴近现有链路);
2. 坐标契约:map z ↔ NED z ↔ rangefinder height ↔ baro relative alt 的转换表先写后编码;
3. 安全限幅:z speed ≤ 0.2 m/s、单步高度 ≤ 0.5 m、ceiling/floor、**上/下方 ESDF clearance 必查**;
4. TF/SLAM stale → 立即保持高度(fail-closed);
5. z 目标要有 goal identity 与完成判据;上升和下降分别测试;
6. 验证三源交叉:Gazebo truth / FCU local position / SLAM z(+rangefinder)。
