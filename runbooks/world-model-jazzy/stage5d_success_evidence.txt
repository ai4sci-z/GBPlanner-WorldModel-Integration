=== STAGE5D 成功率战役记录(2026-07-07,Review_020 落实)===

## 一、C类根因链(全部源码+实测定案,修复入 clean 分支)

1. **探针语义查证**:exploration_probe 在服务拉起后即并发启动;对 String status 话题
   = "等到 ok=True 或预算耗尽"(best 机制);对消息话题 = 类型发现→订阅→取第一条。
2. **C类根因①·预算不覆盖任务**:exploration ProbeTimeoutSec=35s,而 accepted≥3 需
   takeoff(~45s)后再运动若干秒——实测:过的 run 37.08s 踩线拿到 ok,挂的 run 43s 耗尽。
   **基线 accepted 恒=2 同机制**(关门时计时器刚累计到 2)。→ 修复:35→90。
3. **C类根因②·容器上限**:脚本预算 90 超容器 90 上限 → context deadline exceeded 实测
   → 容器上限 90→150。
4. **B类根因①·类型发现小门**(B16 补洞):类型发现循环用 2s 小预算,micro-ROS 话题类型
   传播慢时 45s 消息预算被挡在门外(失败签名 lat=2.2s)→ 类型发现改用全预算。
5. **B类根因②·端点匹配退化**:全预算后实测 /ap/v1/pose/filtered rclpy 等待 48.96s 才匹配
   (B16 孤立测 29s;多 participant 负载下退化)→ frame_contract 预算 45→90+容器 150。
6. **B类根因③·我方负载**:90s 仍现 97.4s 不匹配 → 5c 探针瘦身(去 /ap/v1/cmd_vel 订阅,
   减少 agent 话题晚加入订阅者;消费证据已定档毋需重采)。
   ↑ 修复 1-5 已提交 clean 分支 e7ca9fc(go test 全绿);6 为实验侧脚本。
