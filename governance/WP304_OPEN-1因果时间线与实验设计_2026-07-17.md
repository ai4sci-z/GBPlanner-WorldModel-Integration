## 0. 本文修正了上一版方案的四个方法错误(现场核验后自我纠正)

## 3. 只读证据与结论分级(措辞已降级)

- **F1(降级)**:startup readiness / SLAM / external-nav probe 在**采样时点**均通过
  (`ready=True state=healthy`、`imu_probe ok=True`、`startup_readiness blockers=[]`),失败与成功逐字段一致。
  → 只能说"**降低了 ROS2 管线持续故障的优先级,尚未排除瞬态丢失与事件顺序竞态**";
  **不写**"故障不在 ROS2 管线"、**不写**"每个失败和成功里完全健康"。
- **F2(推断被证伪)**:read-only `strings` 启发式扫描 mav.tlog——`Arm: Accels inconsistent`
  在**成功** run(204428×17、211927×13)与 BIN-present 失败(210849×14)**都**出现,计数区间重叠;
  两次 **no-BIN 扫描中无**该串。→ 结论分级:
  - **BIN-present + Accels inconsistent**:SITL/FCU 多 IMU 一致性机制**强支持**,但"出现≠失败"(成功也出现),
    真正的分界是"是否消解",需连续时序才能证;
  - **no-BIN**:pre-arm/FCU readiness 失败,**根因 UNKNOWN**;
  - 两类**是否同源仍是待证假设**,不得合并。
  - ⚠️ `strings` 扫描是启发式(可能含参数名回显、受捕获窗口影响),**不参与根因判定**。
    **本节 F2 计数已被 §9.1 的 CRC 校验协议解析取代**(新旧计数分栏见 §9.1);此处仅存历史。
- **F3(降级)**:失败 run 一律 ~3m43-44s,成功 ~3m09-14s,差 ~32s ≈ pre-arm 等待到超时;
  tlog 大小与此时长强相关。→ tlog 大小**只作观察特征,不作故障机制或独立分类器**。
- **F4(缺口)**:无逐 run 宿主负载埋点、无 SITL 控制台直存 → 负载相关性**从未被测量**,H1 目前不可证伪。
- **F5(降级)**:runner/probe 生命周期(probes 完即 SIGKILL)**不是当前 pre-arm 失败的直接解释**
  (失败是真·prearm abort、从未 arm,非飞行中被杀);但它是**独立系统缺陷**(GATE-4b 任务),**未被永久排除**。

### 10.4 纯旁路契约(D5)

- D5-01..07:sidecar **零写入被测系统**——不改控制/ArduPilot 参数/调度/readiness/retry;
  `docker logs --follow` 是 json-log 的只读订阅,**不吞 stdout/stderr**(原日志驱动不变);
  rclpy 订阅端与被测系统**同一 ROS_DOMAIN_ID**(否则订不到目标 topic;"独立 domain"是上一版方法错误)、
  **只订不发**:不创建 publisher/service/参数写入,不桥接不转发,QoS 只读订阅——旁路性由
  "零发布"保证,不是由 domain 隔离保证。
- D5-08/09:观测写失败→任务业务结果不变;该 run `evidence_gate=CORRUPT`(telemetry required 缺/损),
  不入验收分母成功项。
- D5-10/11:开关=`WP303_TELEMETRY=on|off`(launcher 环境);off=完全不启动 sidecar,基线行为逐位不变。
- D5-12..17:每文件头记录 batch_id+run_id+process_identity;单文件 JSON=tmp+fsync+rename+目录 fsync
  (复用 WP303 `bc_write_atomic`/`write_json_atomic` 同实现)。**JSONL 不追加已存在文件**
  ("追加+对齐 fsync"是上一版方法错误:崩溃会留半行,破坏逐行可解析):改为**不可变段**——
  记录先缓冲,封存时写 `segment-N.tmp`→fsync→rename `segment-N.jsonl`→目录 fsync;
  已 rename 的段永不再写;段序列与计数由原子索引 `index.json`(同 tmp+fsync+rename)登记。
