## 1. 真实任务句柄(权威生命周期主体)

**选型:批会话(setsid 会话/进程组 PGID)+ 任务登记文件(task record),双件互证。**
锁文件降级为纯互斥,**不再充当生命探针**(草稿的核心错误,见 §10)。

- **task record** = `artifacts/sim/batch_tasks/<batch_id>.task.json`,batch_id=`<脚本名>_<UTCstamp>`。
  字段:{batch_id, script, pid, pgid, pid_starttime(/proc/<pid>/stat 第 22 字段), boot_id
  (/proc/sys/kernel/random/boot_id), log_path, lock_path, expected_runs, created_at,
  monitor_pid(注册制), state, state_history[]}。原子更新=写临时文件+rename。
- **创建者**=批脚本自身,在获得 flock **之后、第一个 run 之前**写盘(消除"监视先于持锁"竞态);
  **持有者**=文件系统;**回收者**=monitor(写终态后归档记录,不删除)。
- **防 PID 复用**:存活判定=(pid,pid_starttime,boot_id) 三元组同时匹配,任一不符=进程已死。
- **父死子活**:权威主体是 PGID(setsid 使 batch=会话首进程);父亡后 `kill -0 -- -PGID`/
  遍历 /proc 同 PGID 仍可枚举子进程(go run 及其子孙默认继承)。
- **容器在、宿主进程不在(或相反)**:容器归 runner 层管理(runner cleanup 是第一责任人);
  monitor 只对"批终态后仍存活、且能从该批各 run 的 runtime 事件日志(service.started 记录的
  ContainerName)反查归属"的容器判残留并登记——**不按名字模式清理**(§6)。
- **明确禁止**:日志文件存在性、tail 进程、锁可获取性,均不得单独作为任务生命证据。

## 2. 状态模型

`STARTING → RUNNING → {SUCCEEDED | FAILED | TIMED_OUT | PRODUCER_CRASHED | CANCELLED}`
+ 两个正交修饰终态:`EVIDENCE_INCOMPLETE`、`CLEANUP_FAILED`。

| 状态 | 进入条件 | 终态 |
|---|---|---|
| STARTING | task record 已建但首个 run 未开始;宽限 ≤ T_start | 否 |
| RUNNING | 首 run 行出现且 (pid,starttime,boot_id) 存活 | 否 |
| SUCCEEDED | producer 正常终止 + 完成标记 + **全部 run rc=0** + 证据完整 + 清理干净 | 是 |
| FAILED | producer 正常终止 + 完成标记 + ≥1 个 run rc≠0 | 是 |
| PRODUCER_CRASHED | (pid,starttime,boot_id) 判死 且 无完成标记 | 是 |
| TIMED_OUT | 超 deadline 且 producer 仍存活(随后进入升级终止序) | 是 |
| CANCELLED | cancel 请求文件出现且被执行 | 是 |
| EVIDENCE_INCOMPLETE | 任一应产物(summary/mission/rosbag/BIN/退出码)缺失,叠加于上述任一终态 | 修饰 |
| CLEANUP_FAILED | 终态后残留进程/容器清理失败或超时 | 修饰 |

**判定优先级(每个轮询周期固定顺序)**:①cancel 请求 → CANCELLED;②producer 已终止 →
按标记+run rc+证据归入 SUCCEEDED/FAILED/PRODUCER_CRASHED(+修饰);③deadline 已过且仍活 →
TIMED_OUT。**因此"到点时恰好发现 producer 已死"判 PRODUCER_CRASHED**(生产者真值优先于
监视者相对时钟)。负责人指定的裁决:

- batch done 但 summary 缺失 → **不算成功**:FAILED 或按终态 + EVIDENCE_INCOMPLETE;
- 某 run rc≠0 但批脚本最终 rc=0 → **FAILED**(逐 run 聚合优先于脚本自身 rc);
- producer 正常退出但子进程残留 → 终态照判 + **CLEANUP_FAILED**(宽限后);
- summary 完整但 rosbag 缺失 → 终态照判 + **EVIDENCE_INCOMPLETE**。

## 3. 成功判定(三轴,不许一个布尔吞三态)

`result = (task_outcome, evidence_status, cleanup_status)`

- task_outcome:producer 退出码 + 完成标记 + 逐 run rc 聚合(来自结构化 run 记录,不再 grep 散文);
- evidence_status:逐 run 检查 summary.json、mission_summary.json、hover_mission_rc.txt、
  rosbag(mcap)、BIN(SITL logs)存在性+非零大小+(可选)sha256;
- cleanup_status:PGID 进程零残留 + 归属容器零残留(运行中口径;历史退出容器另行登记,§6)。

只有三轴全绿 → 退出码 0。

## 5. Partial artifact(取证先于清理,不可逆操作最后)

- crash/timeout 时冻结清单 = 该批全部 run 目录 + 批日志 + task record;
- 写入中文件安全快照:连续 2 个轮询周期大小不变 → 复制;仍在增长 → 记录 size@t 两点为证;
- 每个 run 生成 `_PARTIAL.json` 边车:{reason, present[], missing[], sha256, size, ts};
- summary 缺失时由 monitor 生成 `monitor_failure_index.json`(attempts/airborne/full-pass/fail
  分类 + 各产物路径/哈希/大小 + 生成 commit/config/image)——对齐补充令 §十一/§十二;
- 大二进制(BIN/mcap)不进 Git:Git 只进 index(路径+SHA256+大小+保留策略);LFS/artifact store
  选型待负责人批;
- **清理动作永远排在取证快照与 index 落盘之后**。

## 6. 清理边界

可清理:①自己(monitor)创建的辅助进程;②task record 中 PGID 的存活成员(先 SIGTERM 组,
宽限后 SIGKILL 组);③该批各 run 事件日志登记的 ContainerName 且仍在运行的容器(先给 runner
自身清理留满宽限,monitor 只兜底)。
不可清理:共享基础设施(DDS/Gazebo/ArduPilot 若非本批启动)、其他并行任务(不同 batch_id)、
历史已退出容器(只登记,规则=本方案 §6.1)、未完成取证的任何证据。
硬禁止:模糊 pkill/按进程名猜杀/为"零残留"销毁未登记失败证据。

**§6.1 历史退出容器规则(纳入本方案,回应负责人第三节意见)**:批收口时枚举
`docker ps -a --filter status=exited`,与本批 run 关联者登记(ID/关联 run/退出码/镜像)入
failure index;确认证据落盘后标记"可清理",实际删除动作按负责人批准的保留期执行;
与本批无关的退出容器只登记不动。现存 `zealous_curran` 适用此规则,保留至负责人裁决。

## 8. 并发与竞态(逐项→缓解)

a) producer 写完 done 即释放锁:终态判定不依赖锁;done 标记+record 状态双查(草稿已有 done
   复查,保留)。
b) **monitor 探测时 producer 尚未获得锁**(=fixture-4 真实根因):record 先于 fork 内业务写盘
   + STARTING 宽限期内不判死;锁不作生命探针。
c) 锁文件存在但无人持有:flock 内核语义本就随进程消亡释放;判死只看三元组,锁文件残留无害。
d) producer fork 后父进程退出:主体=PGID,record 存 pgid;父亡不改变组内存活判定。
e) 日志 rename/truncate/rotate:按 (inode,offset) 跟踪,inode 变更即重开;truncate(size<offset)
   → 从 0 重读并记 WARN 事件。
f) 多 monitor 并存:record 内 monitor_pid 注册(原子 rename 抢注);后来者降级为只读观察模式,
   不执行终止/清理。
g) 同一锁名被两批复用(现状真实缺陷,l15/l2/l2fix 共用 /tmp/l1_bisect_batch.lock):
   锁路径改 `/tmp/navlab_batch_<batch_id>.lock` + 全局互斥锁仅用于"同类批不并行"策略位。
h) PID 复用:三元组 (pid,starttime,boot_id)。
i) 系统时间回退:单调时基(§7)。
j) cancel 与自然完成同时:判定序 ①cancel 标志存在但 producer 已终态 → 按终态归类,cancel
   记为 no-op 事件;仅当执行了终止序才判 CANCELLED。
