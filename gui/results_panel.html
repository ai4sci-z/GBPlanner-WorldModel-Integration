① 融合定性与链路

GBPlanner-in-world-model 的桥接式融合——ROS1 原版 GBPlanner 通过自写薄桥(B2.5)接入 ROS2 world-model,在 world-model 仿真里形成 3D 数据链、规划链、控制消费链、去混流运动归因、gate 机制通过与公平对比。不是 ROS2 原生移植(官方无 ROS2 版 GBPlanner)。

融合链路(每一段都有证据文件,非方案想象):

world-model 3D lidar(lidar3d 净增量)/ odom
        ↓  ROS2 → ROS1 自写 TCP 薄桥(官方 ros1_bridge 与 zenoh 均实验判死)
GBPlanner / voxblox 3D 建图 / trajectory 规划
        ↓  ROS1 → ROS2 薄桥回流(/gbp/trajectory,只接 PCI 执行轨迹)
trajectory_to_intent 适配器(fail-closed + Procrustes 坐标对齐 + PD + 诚实计数)
        ↓
world-model FCU intent / cmd_vel(GBP-SIGNATURE 逐位吻合)
        ↓
飞机实际 odom 运动(去混流可归因)+ exploration gate(以 strategy=gbplanner 通过)

🔧 ⑤ 今日修复链时间线(2026-07-07)

1. EKF 参考系真 bug(上游根因,BIN 飞控日志铁证)
external_nav 把 SLAM map 系位置直接喂 AP,而 AP yaw 参考是罗盘世界系——静止无感,一动即发散(位置环正反馈,估计跑飞 34.8m → "stopped aiding" → "EKF variance: position lost")。修复三连: ① EK3_SRC1_YAW 1→6(yaw 与位置同源=外部导航); ② COMPASS_USE/USE2/USE3 → 0(消除罗盘世界系参照); ③ --no-align-yaw-to-fcu(掐断 yaw 循环自证)。 验证:漂移 0.25~0.4 → 0.03 m/s,发散消失;该 bug 同时解释基线 path 0.43~3.80m 巨大方差。
2. 坐标对齐 v6b(适配器侧)
双坐标系同步观测 Procrustes(零滞后)收敛出稳定 map↔AP 映射 R_align = 旋转 −87°(det=+1);针对"胡萝卜"位置目标越过 wp 导致 0.5m 极限环打圈,加近距按比例减速 forward=min(0.08, 0.4·dist) + 诚实 wp_done(预到达剔除)+ 严格 ok 闩锁。
3. 探针预算三连修(B 类波动收敛)
① 探针等待预算 35 → 90s;② 容器超时 → 150s;③ 类型已发现时给全预算等待 publisher 匹配(DDS 慢发现);frame_contract 预算 45 → 90s。修复后 final2 零探针失败复现全绿。

⚖ ⑥ 诚实边界(不宣称清单)

  • 不宣称稳定全绿。修复后小样本:final1 gate 过、final2 全绿、final3 A 类波动;首批 6 run 全绿率 1/6,受 A 类(探索质量)+ B 类(探针/上游)波动共同影响。
  • 不宣称完整 z 向飞行闭环。3D 体现在感知 / 建图 / 规划行为(voxblox zspan、trajectory z 机动),尚未证明完整 z 方向飞行动作闭环。
  • 不宣称 3D 障碍物级对照。Stage5b 是传感 FOV 对照(唯一变量=垂直 FOV),不是障碍物级对照;±5° 变体失败也不能完全归因 3D 输入(单次 run,含 gate 采样时序波动)。
  • 样本量小(n = 6 + 6),对比结论为"同口径下 GBPlanner 显著优于 frontier_lite(50% vs 0%)",非统计学显著性宣称。
  • 方向一致性尚未逐段稳定(final2 探针 direction_consistency=UNSTABLE,段间散布主要来自换向瞬态与执行滞后)——可宣称的是:去混流、消费链、转发忠实、总体可归因、gate 机制全部成立。
